# 接口联调与交付模块需求分析

| 项目 | 内容 |
| --- | --- |
| 模块负责人 | A 与 B 共同负责 |
| 主要参与者 | 两名开发成员、测试与答辩人员 |
| 上游依赖 | 全部业务模块 |
| 主要产物 | RESTful 接口、ApiFox 集合、测试记录、部署说明、结题材料 |

## 1 模块目标

本模块确保 A、B 开发的功能可以在同一工程和数据库中稳定协作，并形成评分所需的接口、测试、优化、过程和部署证据。

联调不能只验证正常返回码，还必须覆盖权限拒绝、非法状态、并发冲突、事务回滚和敏感信息保护。

## 2 RESTful 接口约定

| 约定 | 要求 |
| --- | --- |
| 资源路径 | 使用名词复数，例如 `/api/articles`、`/api/users` |
| 查询 | 使用 `GET`，筛选条件通过查询参数传递 |
| 新增 | 使用 `POST` |
| 完整更新 | 使用 `PUT`，部分更新可以使用 `PATCH` |
| 删除 | 使用 `DELETE`，业务数据按规则逻辑删除 |
| 状态动作 | 使用明确子资源或动作资源，不允许通用接口任意传状态 |
| 响应 | 使用统一业务码、提示、数据和请求标识 |
| 分页 | 页码、页大小、总数和记录集合字段统一 |
| 时间 | 使用统一格式和时区说明 |

## 3 核心接口范围

### 3.1 B 提供

- 注册、登录、退出和当前用户。
- 用户分页、账号启停。
- 角色查询、用户角色设置、角色权限设置。
- 日志分页查询。
- 当前用户上下文、权限注解、日志注解、统一异常和统一响应。

### 3.2 A 提供

- 分类树、新增、编辑、移动、排序、启停和删除。
- 文章新增、详情、编辑、删除、分页和组合查询。
- 提交审核、待审查询、审核通过和退回。
- 单篇发布、批量发布和下架。
- 公开文章列表和详情。

具体路径和字段在 ApiFox 中维护，业务含义以对应模块需求为准。

## 4 联调顺序

### 4.1 第一次联调

目标：证明 A 可以使用 B 的公共能力。

1. B 提供登录、当前用户和权限注解。
2. A 选择一个文章查询和一个文章写入接口接入。
3. 验证未登录 401、无权限 403、有权限成功。
4. 确认 A 没有硬编码用户或自行维护第二套权限判断。

### 4.2 第二次联调

目标：证明跨模块数据关系正确。

1. 管理员创建或准备用户角色。
2. A 创建分类和文章。
3. 文章作者关联真实用户，文章分类关联真实分类。
4. 删除或停用关联对象时符合各模块规则。

### 4.3 第三次联调

目标：跑通核心业务流程。

1. 编辑账号创建文章并提交审核。
2. 编辑账号直接审核，验证 403。
3. 审核账号退回文章。
4. 编辑修改并重新提交。
5. 审核账号通过。
6. 发布账号批量发布。
7. 匿名访问公开接口。
8. 发布账号下架，匿名访问返回 404。

### 4.4 第四次联调

目标：验证工程质量。

1. 检查关键操作日志。
2. 验证参数校验和统一异常。
3. 验证并发编辑和并发审核冲突。
4. 验证批量发布事务回滚。
5. 验证 N+1 优化及返回正确性。

## 5 ApiFox 要求

### 5.1 环境

至少提供：

- 本地环境地址。
- 管理员、编辑、审核、发布和停用账号。
- 测试数据初始化说明。
- 会话或认证信息的获取方式。

测试账号只能使用演示数据，密码和数据库真实凭证不得提交到公开仓库。

### 5.2 用例组织

ApiFox 按模块建立目录，每个核心接口至少包含：

- 一个正常用例。
- 一个参数错误用例。
- 一个未登录或无权限用例，适用时必须提供。
- 一个对象不存在或状态冲突用例，适用时必须提供。

有状态用例必须说明前置数据和执行顺序，避免用例只能成功一次。

## 6 自动化测试重点

建议优先自动化以下仅靠手工容易漏测的场景：

| 场景 | 原因 |
| --- | --- |
| 分类移动到后代节点 | 涉及树形循环判断 |
| 两次使用旧版本编辑文章 | 涉及乐观锁和并发覆盖 |
| 两名审核人同时处理 | 涉及状态竞争 |
| 批量发布中途失败 | 涉及事务完整回滚 |
| AOP 越权调用 | 需要证明接口真实经过代理 |
| 日志与业务事务一致 | 容易留下虚假成功日志 |
| 一对多查询分页 | JOIN 或组装容易造成总数错误 |

## 7 SQL 优化证据

A、B 各准备一个实际案例：

| 负责人 | 案例 | 必须记录 |
| --- | --- | --- |
| A | 文章列表关联分类或作者 | 数据规模、查询条件、优化前后 SQL 次数、结果一致性、执行计划或耗时 |
| B | 用户列表关联角色 | 数据规模、查询条件、优化前后 SQL 次数、结果一致性、执行计划或耗时 |

测试应使用相同环境、数据和查询条件。不能只用单次耗时断言优化有效，也不能为了展示问题而把低效实现留在正式代码中。

## 8 部署和启动要求

1. 提供 JDK、Maven、数据库和服务器版本。
2. 提供数据库创建、SQL 导入和初始化数据说明。
3. 配置文件不得包含真实密码；使用示例配置说明本地参数。
4. 提供完整构建和启动命令。
5. 提供应用地址、ApiFox 环境和演示账号。
6. 在另一台开发机器或干净环境执行一次启动验证。
7. 启动失败时提供常见问题，例如端口占用、数据库连接和字符集。

## 9 过程材料要求

每名成员分别保留：

- 个人需求和任务清单。
- Git 提交记录。
- AI 原始交互及采用范围。
- 人工修改说明。
- 报错信息、复现步骤、定位依据和修复过程。
- ApiFox 或自动化测试结果。
- SQL 优化前后证据。
- 本人负责的结题报告章节和实验总结。

材料必须来自实际开发过程，不能在提交前补造结果。

## 10 最终验收矩阵

| 编号 | 场景 | 主要负责人 | 预期结果 |
| --- | --- | --- | --- |
| INT-01 | 注册、登录、退出 | B | 会话状态正确，密码不泄露 |
| INT-02 | 角色分配及权限撤销 | B | 下一请求按新权限执行 |
| INT-03 | 分类三级树及循环移动 | A | 正常树正确，循环被拒绝 |
| INT-04 | 文章新增、编辑、分页、筛选 | A | 数据和分页正确 |
| INT-05 | 旧版本并发编辑 | A | 后一次返回 409 |
| INT-06 | 编辑账号直接审核 | A 与 B | AOP 返回 403，状态不变 |
| INT-07 | 退回、修改、重新提交、通过 | A | 状态和审核信息正确 |
| INT-08 | 批量发布混入非法文章 | A | 整批回滚 |
| INT-09 | 发布和下架后的公开查询 | A | 只有已发布文章可见 |
| INT-10 | 关键操作日志 | B | 操作者、动作、目标和结果正确 |
| INT-11 | 非法参数和未知异常 | A 与 B | 统一响应且不泄露堆栈 |
| INT-12 | 两个 N+1 优化案例 | A 与 B | 查询次数减少且结果一致 |
| INT-13 | 空库部署启动 | A 与 B | 按文档可完成主流程 |

## 11 交付物

- 完整源代码和依赖配置。
- 建表、约束、索引和初始化数据 SQL。
- 总需求和模块详细需求。
- 项目架构图、E-R 图、业务流程图和数据字典。
- RESTful 接口说明和 ApiFox 导出。
- 功能、权限、异常、并发、事务和 SQL 优化测试记录。
- 部署说明、演示账号、结题报告和实验总结。
- AI 使用、人工修改和 Git 过程材料。

## 12 完成标准

- `main` 分支可以构建和启动。
- 所有 P0 模块需求有对应实现和验证证据。
- 核心流程不依赖手工修改数据库。
- A、B 接口、权限编码、状态和错误语义一致。
- 无阻断缺陷，已知非阻断问题有明确记录。
- 两名成员都能独立解释本人负责模块及协作边界。
