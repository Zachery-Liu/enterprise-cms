# 操作日志与公共机制模块需求分析

| 项目 | 内容 |
| --- | --- |
| 模块负责人 | B |
| 主要使用方 | 全部后台业务模块 |
| 上游依赖 | 用户认证与当前用户上下文 |
| 下游使用方 | 分类、文章、审核发布、接口联调 |

## 1 模块目标

本模块为全部业务接口提供统一响应、参数校验、异常处理、请求标识和操作日志能力，避免 A、B 各自实现不一致的公共机制。

公共机制只处理跨模块的一致性问题，不代替分类、文章和状态机中的领域校验。

## 2 功能需求

| 编号 | 优先级 | 需求 | 业务结果 |
| --- | --- | --- | --- |
| COMMON-01 | P0 | 统一响应 | 正常和异常响应使用一致结构 |
| COMMON-02 | P0 | 分页响应 | 分页接口返回统一分页信息 |
| COMMON-03 | P0 | 参数校验 | 在进入业务逻辑前拒绝明显非法参数 |
| COMMON-04 | P0 | 统一异常 | 将业务异常映射为稳定错误语义 |
| COMMON-05 | P0 | 请求标识 | 每次请求具有可用于排查的标识 |
| LOG-01 | P0 | 操作日志记录 | 保存关键操作及真实结果 |
| LOG-02 | P0 | 日志查询 | 支持分页和多条件筛选 |
| LOG-03 | P0 | 敏感信息保护 | 日志和响应不泄露敏感字段 |
| LOG-04 | P1 | 失败操作记录 | 在不伪造结果的前提下保存重要失败尝试 |

## 3 统一响应

正常响应建议包含：

| 字段 | 说明 |
| --- | --- |
| `code` | 稳定业务码 |
| `message` | 面向调用方的简明提示 |
| `data` | 业务数据，可以为空 |
| `requestId` | 本次请求的排查标识 |

分页响应的 `data` 至少包含：记录集合、总数、页码和页大小。

规则：

1. HTTP 状态码表达请求类别，业务码表达具体错误。
2. 同一种错误在 A、B 模块中使用相同业务码和提示原则。
3. 正常空列表返回成功及空集合，不使用 404。
4. 不在响应中返回 Java 异常类名、SQL、文件路径或堆栈。

## 4 参数校验

公共校验至少覆盖：

- ID 必须为合法正数或符合统一 ID 格式。
- 字符串必填、长度和基础格式。
- 页码、页大小及最大页大小。
- 批量 ID 集合非空、数量上限和重复值。
- 时间范围起止顺序。
- 排序方向和排序字段白名单。

规则：

1. 字段格式问题返回 400。
2. 对象不存在、状态非法和关联限制由业务模块处理。
3. 校验提示应指出字段及原因，但不能包含内部实现细节。
4. 不能只依赖前端表单校验。

## 5 统一异常

| 异常类别 | HTTP 状态 | 示例 |
| --- | --- | --- |
| 请求校验异常 | 400 | 标题为空、页大小超限 |
| 未认证异常 | 401 | 未登录、会话失效 |
| 权限异常 | 403 | 编辑账号执行审核 |
| 对象不存在 | 404 | 分类或文章不可见 |
| 业务冲突 | 409 | 用户名重复、状态非法、版本冲突 |
| 未知异常 | 500 | 未预期的服务端错误 |

未知异常必须写入服务端错误日志并关联请求标识，对客户端只返回通用提示。

## 6 操作日志范围

必须记录的关键操作：

- 登录成功和必要的登录失败摘要。
- 用户启停、用户角色调整和角色权限配置。
- 分类新增、编辑、移动、启停和删除。
- 文章新增、编辑和删除。
- 提交审核、审核通过、审核退回。
- 单篇或批量发布、下架。

普通列表和详情查询默认不记录业务操作日志，避免产生大量低价值数据；安全或调试日志可按需要单独处理。

## 7 日志内容

| 字段 | 说明 |
| --- | --- |
| 操作者 ID | 从当前用户上下文读取；匿名操作允许为空 |
| 操作者名称快照 | 可选，用于展示历史身份 |
| 模块 | 用户、权限、分类、文章、审核发布等 |
| 动作 | 新增、编辑、审核、发布等稳定编码 |
| 目标类型和 ID | 标识被操作业务对象 |
| 结果 | 成功或失败 |
| 摘要 | 必要的非敏感说明 |
| 请求标识 | 与服务端日志关联 |
| 操作时间 | 服务端时间 |

日志不得保存密码、密码摘要、会话标识、完整 Cookie、完整正文或完整请求体。

## 8 日志事务规则

1. 成功日志只能在业务操作真实成功后成立。
2. 业务事务回滚后不能留下“操作成功”的日志。
3. 如果成功日志与业务数据处于同一事务，应保证一起提交或一起回滚。
4. 如果需要记录失败操作，应明确使用独立保存路径，并将结果标记为失败。
5. 日志保存失败是否阻止业务操作必须统一。课程 MVP 建议关键写操作日志失败时业务回滚，以保证评分演示中的可追溯性。
6. 批量操作记录批次摘要和数量，必要时记录失败文章 ID，但不复制全部文章正文。

## 9 日志查询

1. 查询需要 `cms:log:read` 权限。
2. 支持操作者、模块、动作、结果和时间范围筛选。
3. 使用数据库分页并保持稳定排序。
4. 日志只读，不提供普通修改或删除接口。
5. 无查询权限时返回 403。

## 10 异常与边界场景

| 场景 | 预期结果 |
| --- | --- |
| 参数校验失败 | 400，业务 Service 不执行 |
| 未登录访问受保护接口 | 401 |
| 已登录但无权限 | 403 |
| 乐观锁冲突 | 409，并提供可理解提示 |
| 未知空指针或数据库异常 | 500，响应无堆栈且服务端有 requestId |
| 业务事务回滚 | 不留下成功日志 |
| 日志参数包含密码 | 密码字段被过滤 |
| 普通用户查询日志 | 403 |
| 日志查询无结果 | 成功返回空集合 |

## 11 验收标准

- A、B 全部接口使用同一响应和异常格式。
- 400、401、403、404、409 和 500 场景可验证。
- 每个响应包含可用于排查的请求标识。
- 关键操作日志的操作者、目标、动作和结果正确。
- 事务回滚不会留下虚假成功日志。
- 日志和响应中不存在密码、会话标识和内部堆栈。
- 日志分页和组合筛选结果正确。

## 12 不在本阶段范围

- 集中式日志平台、链路追踪系统和外部告警平台。
- 审计日志防篡改存储。
- 复杂日志保留和归档策略。
- 面向大规模生产系统的异步日志队列。
