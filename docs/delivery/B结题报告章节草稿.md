## 2 技术选型与工程结构

项目使用 Java 17、Spring Framework 6.2.15、Spring MVC、MyBatis-Plus 3.5.10 和 MySQL 8.0，以 WAR 部署到外部 Tomcat 10.1。按照课程不使用 Spring Boot 的约束，已经从原 Boot 结构迁移到显式配置的传统 SSM；旧验证记录作为历史保留，新结论使用 SSM 环境重测。

根容器管理业务、数据访问与事务；MVC 子容器管理 Controller、统一异常与请求拦截。数据源、插件链和事务管理器统一配置。架构图、RBAC 关系图、权限流程及日志事务图见[B 模块架构与流程图](../design/B模块架构与流程图.md)。

## 3 需求与数据库设计

B 的主要需求为注册、登录退出、当前用户查询、用户分页、账号启停、角色与权限查询及分配、细粒度权限校验、操作日志记录与筛选。异常场景包括重复注册、非法输入、未认证、越权、权限撤销、账号停用、版本冲突和事务失败。

六张表为 `sys_user`、`sys_role`、`sys_permission`、`sys_user_role`、`sys_role_permission`、`sys_operation_log`。前两种关联通过独立关系表表达多对多授权。唯一约束防止重复账号、编码和授权；外键保护引用关系；主数据使用逻辑删除，日志只追加。时间统一为 UTC 毫秒精度，分页在时间相同时按 ID 稳定排序。完整字段及索引见[数据库设计](../design/B模块数据库设计.md)。

## 5 重难点与优化

第一，传统 SSM 有父子容器的代理边界。权限切面显式注册到 Controller 所在的 MVC 容器，接入约定要求受保护入口自己声明注解，并通过测试展示 `this` 内部调用绕过代理的风险。

第二，数据库业务与成功日志必须保持一致。日志切面参与业务事务，成功日志失败使业务回滚；事务完成后失败日志独立尝试保存，避免回滚抹去失败记录。事务异常与日志故障分别测试，不能用会话日志的策略替代数据库写操作策略。

第三，用户角色列表容易引入逐用户查询。正式实现先分页用户，再批量取角色并组装。测试中的逐用户对照分别需要 12、22、102 次 SQL；每页 10、20、100 条的正式实现均为 3 次。真实 MySQL 各跑 5 轮，完整响应相同。只测得查询次数下降，未声称耗时按同样比例下降。

第四，测量工具自身也需验证。初版 MyBatis 计数探针在全量多上下文运行中漏计 COUNT，改为 JDBC 连接层计数后重新跑全量与真实 MySQL；复现、定位、修改及回归见[答辩提纲中的问题案例](B评分对照与答辩提纲.md)。
