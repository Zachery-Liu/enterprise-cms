# B-12 角色权限查询接口

日期：2026-10-08。基于 V1.0 公共契约和远程新版工程，权限编码保持不变。

## HTTP 接口

以下接口均为 GET，要求 B-09 登录会话；响应使用 `ApiResponse<T>`，包含 `code`、`message`、`data`、`requestId`。读取操作不要求 CSRF Token。

| 地址 | 所需有效权限 | data |
| --- | --- | --- |
| `/api/roles` | `cms:role:assign` | 角色数组 |
| `/api/roles/{id}` | `cms:role:assign` | 单个角色 |
| `/api/roles/{id}/permissions` | `cms:permission:manage` | 该角色当前有效权限数组 |
| `/api/permissions` | `cms:permission:manage` | 权限目录数组 |

角色和权限 DTO 均只含 `id`、`code`、`name`、`description`、`status`，其中 description 可以为 null。不直接序列化持久层 Entity。列表按 code、id 排序。

角色目录、角色详情和权限目录排除逻辑删除记录，但保留停用记录及其状态，供管理人员识别。角色权限接口返回有效权限：停用角色返回空数组；停用或逻辑删除权限不会出现在该数组中。它不是用于恢复停用对象的完整原始授权关系快照。

| 场景 | HTTP 状态 |
| --- | --- |
| 未登录、会话失效、当前账号停用或删除 | 401 |
| 已登录但缺少对应有效权限 | 403 |
| 已授权请求的 ID 非正整数或超出 Long 范围 | 400 |
| 已授权请求的角色不存在或已逻辑删除 | 404 |
| 列表或有效权限为空 | 200，data 为 `[]` |

鉴权优先于详情 ID 校验。ADMIN 角色没有硬编码绕过；授权查询实时读取数据库，撤销关系、停用角色或权限在下一请求生效。当前通过 `PermissionQueryGuard` 显式保护以上入口，B-14 再接入统一权限注解与 AOP。

## B 内部批量查询

`RbacQueryService` 为后续 B-10、B-13 提供以下能力；这些方法不是新增 HTTP 批量入口，A 读取作者应使用后续 B-10 的公共 `UserReader`。

| 方法 | 返回及语义 |
| --- | --- |
| `rolesForUsers(Collection<Long>)` | 用户 ID 到有效角色列表的映射 |
| `permissionsForRoles(Collection<Long>)` | 角色 ID 到有效权限列表的映射 |
| `effectivePermissionCodes(long)` | 用户所有有效角色的去重权限编码，按编码排序 |

批量输入最多 500 项，先检查原始数量再去重。null 集合、null 元素和非正 ID 返回校验错误；空集合返回空映射且不访问数据库。映射保留每个请求 ID：无关系、不存在、停用或已删除对象对应空列表。结果映射及列表不可修改。

用户角色查询要求账号 ACTIVE、角色 ENABLED，均未逻辑删除；角色权限查询要求角色和权限 ENABLED 且未逻辑删除。两张关系表没有状态或逻辑删除字段，删除关系后自然不再匹配。每个非空批量方法执行一条关联查询，不逐用户或逐角色查询。

## 接入边界

本批不新增 SQL 迁移，不实现角色分配或权限配置写接口，不修改 A 的内容表。B-10 当前用户、B-13 授权写入和 B-14 AOP 仍按任务清单推进。MySQL 8.0、ApiFox 和 A/B 联调尚未验收。
