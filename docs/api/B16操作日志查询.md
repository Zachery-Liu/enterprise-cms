# B-16 操作日志查询

日期：2026-10-11。基于 B-15 `f9abceb`，分支 `feat/operation-log-query`。传统 SSM / JDK 17 / 外部 Tomcat，沿用既有日志表，无新增 SQL 迁移。

## 1 接口

`GET /api/operation-logs`，需要登录且拥有 `cms:log:read`。部署 WAR 时加上下文路径，例如 `http://localhost:8080/enterprise-cms/api/operation-logs`。

使用现有 Session Cookie，不需 CSRF 请求头。响应带 `Cache-Control: no-store`。未登录返回 401；无权限返回 403，ADMIN 角色也不能绕过权限检查；撤权在下一次请求生效。

## 2 查询参数

所有参数可省略；提供时必须有效，空字符串不等于省略。未知参数或同名参数重复出现返回 400。

| 参数 | 规则 |
| --- | --- |
| page | 正整数，默认 1，须保证分页偏移量不溢出 |
| size | 1～100，默认 20 |
| operatorId | 操作者正整数 ID，精确匹配 |
| operatorName | 1～100 字符，不能全为空白，匹配历史名称快照 |
| module | 例如 AUTH、USER、ROLE、ARTICLE；最多 64 位，以大写字母开头，其后允许大写字母、数字、下划线 |
| action | 例如 LOGIN、ASSIGN_ROLES；格式同 module |
| result | SUCCESS 或 FAILURE |
| from | 含时区的 ISO 8601，包含开始时刻 |
| to | 含时区的 ISO 8601，包含结束时刻 |

各条件按 AND 组合，名称使用数据库等值比较，遵循 MySQL `utf8mb4_unicode_ci` 排序规则（不区分大小写），不支持模糊通配符。只按 ID 查询时省略 operatorName，以免混淆历史快照与现账号名称。

时间统一转换为 UTC，精度最多毫秒，与 `DATETIME(3)` 一致；转换后的 UTC 年份支持 1000～9999，from 不得晚于 to，可单独提供任一边界。不带偏移量的时间返回 400。在 URL 中使用 `+08:00` 时须编码为 `%2B08:00`；ApiFox 参数编辑器通常会编码，直接粘贴 URL 时需留意。

固定按 `created_at DESC, id DESC` 排序，不接受客户端排序字段。使用 MyBatis-Plus 数据库分页，同一请求的总数与结果在只读 REPEATABLE_READ 事务中查询。不同请求间若新增日志，页码分页仍可能移动，未承诺跨请求固定快照。

## 3 响应

沿用 `ApiResponse<PageResponse<OperationLogView>>`：

```json
{
  "code": "OK",
  "message": "成功",
  "data": {
    "records": [
      {
        "id": 100,
        "operatorId": 1,
        "operatorName": "admin",
        "module": "AUTH",
        "action": "LOGIN",
        "targetType": "USER",
        "targetId": 1,
        "result": "SUCCESS",
        "summary": "AUTH / LOGIN / SUCCESS",
        "errorCode": null,
        "requestId": "example-request",
        "ipAddress": "127.0.0.1",
        "createdAt": "2026-10-11T01:00:00.123Z"
      }
    ],
    "total": 1,
    "page": 1,
    "size": 20
  },
  "requestId": "example-query"
}
```

示例字段值仅为说明；成功 code/message 以公共响应实现为准。records 中的 requestId 是被记录操作的标识，最外层 requestId 是本次查询标识。匿名失败登录的 operatorId/operatorName 可以为空；退出日志名称也可能为空。

无匹配返回 records=[]、total=0；超出最后一页返回 records=[]，total 仍是全部匹配数量。日志保留历史名称，不联查当前用户覆盖快照。普通查询不新增操作日志，不提供日志修改、删除接口。

## 4 ApiFox 验收

导入同目录 [B16操作日志查询.postman_collection.json](B16操作日志查询.postman_collection.json)。这是准备好的请求与断言集合，不代表已经完成人工 ApiFox 点测。

1. 使用隔离测试环境，启用 Cookie，清除该服务器的旧 Cookie。
2. 设置 baseUrl、adminUsername、adminPassword、plainUsername、plainPassword；管理员须有 cms:log:read，普通账号不能有该权限。
3. 调整 from/to 为所需范围；operatorId 会在管理员登录后自动取得。
4. 按序执行 18 个请求：未登录拒绝、管理员登录、分页、组合查询、时间范围、空结果、参数错误、退出、普通账号拒绝、退出。
5. 核对无泄密字段，查询不新增日志；手动组合筛选并检查分页。
6. 如需验证撤权，使用现有 B-13 授权入口先记录原配置，撤销 cms:log:read 后用原会话查询应为 403；恢复原配置后为 200。集合不自动改动授权。

集合中的脚本使用 Postman 兼容语法，导入后需确认 ApiFox 保留断言。自动化代码已覆盖同会话撤权、历史快照、只读方法限制等，实际运行结果见验证记录。

## 5 本轮边界

本轮完成 B-16 清单中的只读接口与验收用例。管理页面属于后续前端交付，本仓库暂未提供；A 业务日志仍待双方接入联调。日志正文和敏感字段的写入限制继续遵守 [B-15 说明](B15操作日志接入.md)，本查询不新增敏感数据来源。
