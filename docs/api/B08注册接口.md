# B-08 用户注册接口

实现日期：2026-10-04。基于新版公共契约，使用 `com.zachery.cms`、Session CSRF 令牌和 PBKDF2-HMAC-SHA256。登录、退出和登录后的令牌轮换留待 B-09，本次注册不会自动登录。

## 1 数据准备与默认角色

在已经执行 B 的 `sql/001_identity_schema.sql` 和 `sql/003_identity_seed.sql` 的项目库中，额外执行：

```text
sql/004_registration_default_role.sql
```

该增量脚本创建普通角色 `USER`，主键由数据库生成，不分配初始权限；原有 ADMIN、EDITOR、REVIEWER、PUBLISHER 的 ID 和权限不变。再次执行不会重复创建，也不会重新启用已停用/删除的 USER 角色。已有 001、003 历史脚本没有改写，应用启动时不会自动执行 004。

服务器配置 `cms.registration.default-role-code` 默认是 `USER`，可由环境变量 `CMS_REGISTRATION_DEFAULT_ROLE` 配置。它是部署者控制的权限策略，不能从注册请求中取值；普通部署保持 USER，不配置为管理角色。默认角色不存在、停用或已删除时返回 409，账号和关系均不落库。

原 B-01 只初始化四个业务角色，B-08 为满足“普通注册必须有默认角色”补充了 USER。此项是注册实现的增量说明，不改变既有业务角色编码；仍需在 A/B 联调时一起确认部署数据。

## 2 获取 CSRF 令牌

```http
GET /api/auth/csrf-token
```

匿名可调用；服务端创建或复用 Session，返回 `Cache-Control: no-store`。客户端必须保留 Session Cookie。

```json
{
  "code": "OK",
  "message": "成功",
  "data": { "token": "服务端返回的43字符令牌" },
  "requestId": "本次请求标识"
}
```

令牌含 256 位随机数据，采用 URL 安全 Base64 编码。同一 Session 内重复获取返回同一令牌。注册写请求必须携带该 Session 的 Cookie 及 `X-CSRF-Token`；缺失、非法或来自其他 Session 的令牌返回 403 `AUTH_FORBIDDEN`。

CSRF 拦截器覆盖 `/api/**` 中除 GET、HEAD、OPTIONS 外的方法，为后续 B/A 写接口提供相同前置规则。它不是登录或角色权限校验，不能替代 B-09、B-14。

## 3 注册请求

```http
POST /api/auth/register
Content-Type: application/json
X-CSRF-Token: 上一步data.token的值
Cookie: 使用上一步获得的Session Cookie
```

```json
{
  "username": "ordinary_user",
  "password": "ExamplePass123!",
  "displayName": "普通测试用户"
}
```

上面密码只是接口示例，不是初始化账号凭据。

| 字段 | 规则 |
| --- | --- |
| username | 必填；去除首尾空白、规范化为小写；3～64 位 ASCII 字母、数字、下划线、点或连字符 |
| password | 必填且不能全为空白；8～128 长度；不去除首尾空白，不强制字符组合 |
| displayName | 可省略，默认使用规范化用户名；提供时去除首尾空白，必须为 1～100 长度 |

角色、权限、状态、主键、逻辑删除和审计字段不属于注册 DTO；客户端额外提交这些字段会被忽略。服务端固定创建 ACTIVE 账号，只分配服务器配置的默认角色。

## 4 成功与错误

成功返回 HTTP 201，示例：

```json
{
  "code": "OK",
  "message": "成功",
  "data": {
    "id": 5,
    "username": "ordinary_user",
    "displayName": "普通测试用户",
    "status": "ACTIVE",
    "createdAt": "2026-10-04T00:00:00.000Z"
  },
  "requestId": "本次请求标识"
}
```

ID 和时间仅为示例。响应不返回密码、摘要、Session 标识、CSRF 令牌或角色关系实体。请求 DTO 的字符串输出及通用序列化也隐藏密码。

| 情况 | HTTP / 业务码 |
| --- | --- |
| 字段不合法 | 400 / COMMON_VALIDATION_ERROR，data.errors 包含字段与提示 |
| CSRF 令牌缺失、错误或会话不匹配 | 403 / AUTH_FORBIDDEN |
| 重复用户名（含逻辑删除账号占用的用户名） | 409 / COMMON_CONFLICT |
| 默认角色不存在或不可用 | 409 / COMMON_CONFLICT |
| 未预期异常 | 500 / COMMON_INTERNAL_ERROR |

有效令牌是参数校验的前置条件。没有令牌的非法请求会先收到 403，不能用于演示字段校验的 400。

## 5 密码、事务和部署配置

- 摘要格式严格匹配 B-01：`{pbkdf2-sha256}600000$Base64盐$Base64摘要`。
- 使用随机 16 字节盐、600000 次迭代、32 字节输出，比较时使用 `MessageDigest.isEqual`。
- 不接受未知算法、不受限的迭代次数或畸形摘要；不会为注册请求计算客户端提供的摘要格式。
- 用户与角色关系在一个事务中创建。默认角色读取加行锁，防止检查和写入期间角色被停用或删除；关系写入失败回滚用户。
- 不依赖“先查再插”判断用户名唯一，数据库唯一约束负责重复与并发兜底。
- Session 空闲超时 30 分钟，Cookie 为 HttpOnly、SameSite=Lax、Path=/。HTTPS 部署应设置 `CMS_SESSION_COOKIE_SECURE=true`；本机 HTTP 调试默认 false。
- 不开放携带凭据的跨域规则；接口默认供同源客户端使用。
- 本次没有修改现有 MySQL 数据，部署者需在正确的项目库执行增量脚本；账号、密码和代理配置不写入 Git。
