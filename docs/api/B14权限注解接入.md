# B-14 权限注解接入

更新：2026-10-11。开发分支：`feat/security-aop`，基于迁移交付 `c5bf818`。B 实现及现有接口接入已完成，A 的真实分类/文章接口仍待联调。

## 1 注解用法

导入 `com.zachery.cms.security.annotation.RequirePermission`，在由 Spring MVC 管理的 Controller 的 **public、非 final 实现方法**上声明一个权限：

```java
@GetMapping("/api/categories")
@RequirePermission("cms:category:read")
public ApiResponse<List<CategoryView>> categories() {
    return ApiResponse.ok(categoryService.list());
}

@PostMapping("/api/articles")
@RequirePermission("cms:article:create")
public ApiResponse<ArticleView> create(@Valid @RequestBody CreateArticleRequest body) {
    return ApiResponse.ok(articleService.create(body));
}
```

以上是接入示意，DTO、Service、对象权限及文章状态约束由 A 实现；本分支没有新增 A 的业务 Controller 或内容表。

注解中的值必须精确匹配公共契约里的权限编码；一个方法一个核心权限，不支持角色名、通配符或 AND/OR 表达式。ADMIN 也需要有实际有效授权。缺失注解的后台接口仅有登录和 CSRF 保护，不会自动推断细粒度权限，因此每个管理入口都要审查权限声明。

## 2 执行顺序与返回

1. Session 拦截器读取数据库检查账号可用性，未登录/账号停用或删除返回 401；失效账号的会话被清除。
2. CSRF 拦截器校验写请求；缺少或错误令牌返回 403。
3. MVC 调用 Controller 代理，权限切面读取 `CurrentUserContext` 的请求内有效权限快照，缺少所需权限返回 403。
4. 允许后才进入业务方法；A 继续校验对象归属、参数和状态流转。

统一错误码分别为 `AUTH_UNAUTHENTICATED` 和 `AUTH_FORBIDDEN`，保留 requestId。参数解析/Bean Validation 可能先于方法切面执行，因此不以任意非法请求的错误优先级推断是否有权限。

角色或权限停用、删除，以及授权撤销在下一请求生效，不需要重新登录。权限快照不跨请求缓存。B-13 分配 Service 在获取数据库锁后重新检查操作者和权限，防止排队期间授权已被撤销；不能用切面替代该事务内复核。

| GET `/api/roles` | `cms:role:assign` |
| GET `/api/roles/{id}` | `cms:role:assign` |

上述入口已从手工 `PermissionQueryGuard` 转为注解，路径、请求和响应不变。当前用户与退出只要求有效登录；登录、注册和 CSRF 获取按原匿名约定处理。

## 4 匿名接口与代理边界

公开文章只读查询由 A 在具体方法上标记 `@AnonymousAccess`，并自行确保只返回可公开的数据。不要给整个 `/api/**` 放行。`@AnonymousAccess` 不跳过 CSRF，匿名写接口仍须令牌。

同一方法禁止同时标 `@AnonymousAccess` 与 `@RequirePermission`：测试已验证此冲突不会放行，但会使接口无法正常使用。

`PermissionAspect` 显式导入 `WebConfiguration`，只作用于 MVC 子容器中的代理。不要在根容器重复扫描 Controller，不要只把权限注解放在 Service 或接口声明上。Controller 类及被保护方法不得 final，方法不得 private/static；不得通过 `new`、取出代理原对象、或同类内部 `this.method()` 调用来依赖切面鉴权。共用业务放入 Service，各 HTTP 入口各自声明权限。

这些限制来自 Spring 的代理语义，参见 [Spring 6.2 AOP 代理说明](https://docs.spring.io/spring-framework/reference/6.2/core/aop/proxying.html)和[容器级 AOP 配置说明](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/context/annotation/EnableAspectJAutoProxy.html)。没有启用编译期/加载期织入，也没有声称可以拦截同类内部调用。

2026-10-12 补充可运行证据：PermissionAspectTest 的 selfInvocationBypassesAdviceSoEveryExternalEntryNeedsItsOwnPermission 对比直接代理调用、未保护入口内部调用和入口自身声明权限三种情况。风险示例仅位于测试，不在正式 WAR。不能把“已有切面”当作漏写入口权限也安全的证明。
