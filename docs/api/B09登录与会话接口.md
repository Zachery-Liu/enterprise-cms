# B-09 登录、退出与会话接口

实现日期：2026-10-04。基于 B-08 注册与 CSRF 能力。当前只返回登录账号的基础信息；包含角色/权限集合的 `/api/auth/me`、`CurrentUserContext` 和 `UserReader` 属于 B-10。

## 1 登录顺序

1. 调用 `GET /api/auth/csrf-token`，保留返回的 Session Cookie 和 `data.token`。
2. 用相同 Cookie 与令牌调用 `POST /api/auth/login`。
3. 登录成功后必须接收服务端更新的 Cookie；旧会话 ID 不再有效。
4. 再调用 `GET /api/auth/csrf-token` 获取登录后轮换的新令牌。旧令牌不能用于后续写请求。

```http
POST /api/auth/login
Content-Type: application/json
X-CSRF-Token: 登录前获取的令牌
Cookie: 使用获取令牌时的Session Cookie
```

```json
{
  "username": "ordinary_user",
  "password": "ExamplePass123!"
}
```

示例应替换为实际注册账号及其密码，不是种子账号的默认凭据。本次未修改或重置初始化账号的密码。

用户名去除首尾空白并转小写；密码保持原样，不能为空白且最长 128。登录不重复施加注册的最低密码长度规则，以兼容既有合法摘要。客户端发送 userId、角色或权限字段不影响实际身份。

成功返回 HTTP 200，响应带 `Cache-Control: no-store`：

```json
{
  "code": "OK",
  "message": "成功",
  "data": {
    "userId": 5,
    "username": "ordinary_user",
    "displayName": "普通测试用户",
    "status": "ACTIVE"
  },
  "requestId": "本次请求标识"
}
```

服务端只把 Long 类型的用户 ID 写入 Session 键 `CMS_CURRENT_USER_ID`，不在会话中缓存可长期失效的权限集合。密码、摘要、Session ID 和 CSRF 令牌不进入登录响应。

## 2 登录失败

| 情况 | 结果 |
| --- | --- |
| 字段为空或超过长度上限 | 400 / COMMON_VALIDATION_ERROR |
| 缺少或使用错误 CSRF 令牌 | 403 / AUTH_FORBIDDEN |
| 用户不存在、密码不正确、停用或已逻辑删除 | 401 / AUTH_UNAUTHENTICATED，统一提示“账号或密码不正确，或账号不可用” |
| 会话在密码验证期间失效 | 401 |
| 同一会话的令牌在验证期间已被其他登录轮换 | 403，需要重新获取令牌 |

未知或逻辑删除账号同样进行完整密码推导，避免明显的“未查到用户就立即返回”。这不是精确的恒定响应时间或登录限流保证。失败不会建立新登录态；已有合法登录态不会因另一次错误密码尝试而主动清除。

## 3 后台请求与匿名接口

`/api/**` 下映射到 Controller 方法的接口默认需要登录。每次请求根据 Session 用户 ID 重新读取账号；账号停用、删除或不存在时销毁会话并返回 401。客户端的用户 ID 参数和头不能替代服务器 Session。

显式匿名注解为 `com.zachery.cms.security.annotation.AnonymousAccess`，仅作用于方法。当前匿名方法包括获取 CSRF 令牌、注册、登录和退出。A 后续公开内容查询也需要显式声明匿名方法。

匿名声明不会跳过 CSRF。拦截顺序为：基础登录检查（order 0）→ CSRF（order 10）→ 业务方法。没有登录的受保护写请求先返回 401；已登录但写请求令牌错误返回 403。

本批仅检查账号身份和状态，尚无 B-14 细粒度权限切面。不得把“登录后能够访问”当成管理员授权；新增管理接口还必须接入后续权限校验。

## 4 退出

```http
POST /api/auth/logout
X-CSRF-Token: 当前会话最新令牌
Cookie: 当前Session Cookie
```

返回 HTTP 200、`code=OK`、`data=null`，并设置 `Cache-Control: no-store`。服务端使整个 Session 失效，令牌随会话销毁；退出后重用旧 Cookie 访问受保护接口得到 401。

“重复退出安全”仍遵守写请求的 CSRF 契约：退出后先重新获取匿名会话的令牌，再次退出返回 200；直接复用已经销毁的会话和旧令牌返回 403，不会绕过 CSRF 或产生 500。重复退出不修改账号状态。

## 5 Cookie、日志与部署

- Session 空闲超时 30 分钟，Cookie 使用 HttpOnly、SameSite=Lax、Path=/。
- 登录使用 Servlet `changeSessionId()`，由容器更新 Cookie 并使旧 ID 失效。
- 本机 HTTP 保持 Secure=false；HTTPS 部署使用 `CMS_SESSION_COOKIE_SECURE=true`。
- 认证事件摘要写入服务端日志，仅含固定模块/动作/结果、成功时的用户 ID 和 requestId。没有记录用户名输入、密码、摘要、Cookie、CSRF 令牌或完整 Session ID。
- 本批服务端摘要日志不等同于 `sys_operation_log` 操作日志；数据库审计日志仍留到 B-15。
- 不新增数据库迁移。普通注册继续需要 B-08 的 `004_registration_default_role.sql`；此次未对用户 MySQL 执行脚本。
