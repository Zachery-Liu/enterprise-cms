# B-15 操作日志接入

日期：2026-10-11。分支：`feat/operation-log`，基于 B-14 `fcbff83`。使用已有 `sys_operation_log` 表，不新增 SQL 迁移。

## 1 已接入操作

| 模块 / 动作 | 入口 | 目标 |
| --- | --- | --- |
| AUTH / REGISTER | RegistrationService.register | 注册成功返回的用户 ID；匿名操作者为空 |
| USER / ASSIGN_ROLES | RbacAssignmentService.setUserRoles | 用户 ID |
| ROLE / ASSIGN_PERMISSIONS | RbacAssignmentService.setRolePermissions | 角色 ID |
| AUTH / LOGIN | 完成账号校验与 Session 轮换后的 Controller | 已验证用户 ID；失败登录不记录输入用户名 |
| AUTH / LOGOUT | SessionController.logout | 销毁前 Session 中的用户 ID，匿名退出为空 |

日志字段包含可信操作者、名称快照、模块、动作、目标类型/ID、真实结果、固定摘要、安全错误码、requestId、连接来源 IP 和 UTC 时间。名称快照使用已验证用户名；退出时名称可为空，不信任客户端传入的操作者字段或 `X-Forwarded-For`。

摘要固定为 `模块 / 动作 / 结果`，不复制请求体，也不保存权限勾选前后的完整差异。普通查询不记录业务日志。B-16 日志查询接口和页面尚未实现。

## 2 A 的注解用法

优先在负责一次业务写入的 public、非 final Service 方法上标注：

```java
@Transactional
@OperationLog(module = "ARTICLE", action = "UPDATE",
        targetType = "ARTICLE", targetIdExpression = "#articleId")
public ArticleView update(Long articleId, UpdateArticleRequest request) {
    // A 实现对象权限、状态规则及数据库更新。
    return updatedArticle;
}

@Transactional
@OperationLog(module = "CATEGORY", action = "CREATE",
        targetType = "CATEGORY", targetIdExpression = "#result.id")
public CategoryView create(CreateCategoryRequest request) {
    return createdCategory;
}
```

上述返回变量是用法示意，不是已实现的 A 业务。导入类名固定为 `com.zachery.cms.logging.annotation.OperationLog`。每个完整操作选一个注解位置，避免 Controller 和对应 Service 同时标注而重复记录。

| A 的操作 | 建议 module / action / targetType |
| --- | --- |
| 分类新增、编辑、移动、启停、删除 | CATEGORY / CREATE、UPDATE、MOVE、ENABLE、DISABLE、DELETE / CATEGORY |
| 文章新增、编辑、删除 | ARTICLE / CREATE、UPDATE、DELETE / ARTICLE |
| 提交、审核通过、审核退回 | ARTICLE / SUBMIT、APPROVE、REJECT / ARTICLE |
| 发布、下架 | ARTICLE / PUBLISH、OFFLINE / ARTICLE |

module/action/非空 targetType 使用大写字母开头的稳定编码，只含大写字母、数字和下划线，最多 64 字符。批量操作用 BATCH_PUBLISH/BATCH_OFFLINE 等动作；当前单条目标字段不支持 ID 列表和批次数量表达式，不应把列表强行塞进 targetId。需数量/逐项日志时另行扩展契约，不能伪造单个对象 ID。

## 3 目标 ID 表达式

使用受限、只读 SpEL 路径：`#articleId`、`#id`、`#p0`、`#a0`、`#request.articleId`、`#result.id`、`#result.data.id`、`#result.body.data.id`。位置参数别名对应的标量参数必须在源码中命名为 id 或以 Id 结尾。

只提取正 Long 范围的数字 ID。失败路径不读取 `#result`，解析失败、溢出、非数字或缺失目标记录为空；回滚的新建对象不能保留未提交结果里的 ID。

不支持方法调用、类型引用、Bean 引用、赋值、算术或任意属性访问；属性只允许 id、以 Id 结尾的字段以及 data/body 包装层。密码、Token、Cookie、Session 等敏感名称不可作为目标来源。参数对象不被序列化，异常原消息和堆栈不会写入业务日志。

## 4 事务与故障策略

**数据库关键写入：成功日志与业务数据处于同一事务。** 日志插入失败会使业务回滚；随后尝试在独立事务保存 FAILURE。外层事务之后回滚或提交失败时，成功日志随之回滚，不留下虚假 SUCCESS。

事务拦截器顺序为 0，日志切面为 200；先确定 Service 的事务，再加入当前事务保存业务和日志。没有事务的同步 Controller 注解会建立 READ_COMMITTED 的 REQUIRED 事务。真实 Spring Controller 代理也支持该注解，但 A 优先使用 Service 作为一致的事务边界。

传统 Spring 事务现统一使用 `rollbackOn=ALL_EXCEPTIONS`：受检异常也默认回滚，避免日志标记回滚后外层试图提交并掩盖原异常。不要给带日志的写方法配置 `noRollbackFor` 或以抛异常表示业务成功。仅验证同一 DataSource 下同步 JDBC 的 REQUIRED、REQUIRES_NEW；不将 NESTED/savepoint、异步任务或外部系统副作用算作已验收。

REQUIRES_NEW 的已提交业务及其日志不会因调用方另一个事务回滚而消失。不要在 Controller 的日志事务中调用另一个独立提交的业务，再期待 Controller 失败能撤销该独立事务；需要原子提交时，各业务步骤使用同一个 REQUIRED 边界。

**失败记录：** 在实际回滚完成后通过独立事务保存。若失败日志也无法写库，只输出含 requestId、固定模块/动作/结果的告警，不替换原业务异常，不输出 SQL、参数或密码。

**登录/退出：** Session 操作不能随数据库回滚，因此用独立日志路径。日志库故障不把已经完成的登录/退出改成相反结果；保留安全控制台记录和告警。这个例外不适用于数据库关键写操作。

## 5 保护范围

权限注解仍放 Controller，日志注解优先放 Service。根容器中的日志切面可由 MVC 子容器发现，测试已覆盖两层代理。只使用 Spring 管理的 public、非 final 方法；同类内部调用、手动 new 和非代理对象不会触发切面。

Session/CSRF 拦截器、MVC 参数校验或权限切面在方法执行前拒绝的请求，不会触发业务日志。本功能不是全部 HTTP 访问日志。Service 内实际发生的业务失败会记录；A 不能捕获异常后返回“错误对象”却要求切面自动判断失败，应按公共异常契约抛出业务异常。

## 6 查看与联调

目前可在专用测试库执行只读查询：

```sql
SELECT id, operator_id, operator_name, module, action, target_type, target_id,
       result, summary, error_code, request_id, created_at
FROM sys_operation_log
ORDER BY id DESC
LIMIT 20;
```

A 的真实分类、文章、审核、发布接口还需联合验收。B 已用测试业务和实际身份/RBAC 入口验证成功、失败及回滚；测试示例不是 A 的实际业务实现。测试结果见[B-15 验证记录](../verification/B15操作日志验证记录.md)。

事务依据：[Spring 6.2 TransactionSynchronization](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/transaction/support/TransactionSynchronization.html)规定回滚后的持久化需独立事务；表达式使用[只读 SimpleEvaluationContext](https://docs.spring.io/spring-framework/reference/6.2/core/expressions/evaluation.html)，再限制允许的 ID 路径。
