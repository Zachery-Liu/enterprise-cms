## 3 接入边界

| 能力 | A 的接入方式 | 检查点 |
| --- | --- | --- |
| 工程 | 复用 RootConfiguration、WebConfiguration、PersistenceConfiguration | 不加 Boot，不建立第二套数据源/事务/登录 |
| 身份 | 注入 CurrentUserContext，写操作调用 getRequiredUser | 作者/审核人来自服务端，不能采信请求体操作者 |
| 作者展示 | 注入 UserReader，先收集本页 authorId 后调用一次 findByIds | 返回 Map<Long,UserSummary>；不访问 B Mapper，不逐文章查询 |
| 权限 | 在 MVC Controller 的 public、非 final 实现方法标 RequirePermission | 每个后台入口独立声明；不能只给被内部调用的方法加注解 |
| 日志 | 在实际写事务 Service 标 OperationLog | 模块/动作大写稳定编码；目标表达式用 #articleId 或 #result.id 等 ID 路径 |
| 公共响应 | ApiResponse、PageResponse、BusinessException | HTTP 状态和业务码一致，响应带 requestId |
| 公开查询 | 明确标 AnonymousAccess 的只读入口 | A 自行过滤未发布内容；匿名标记不放行整个 API |
| 事务 | 同步单数据源，沿用 B 事务管理器 | 默认受检异常也回滚；成功业务与日志同事务 |
| 扫描 | content 组件；content.persistence.mapper 和 mapper/content XML | 包路径以现有扫描配置为准，接入后验证实际 Bean/SQL |

UserReader 一次最多 500 个输入 ID，先校验原始数量再去重；空集合返回空 Map。停用作者仍可返回摘要以展示历史记录，删除/不存在作者不在 Map 中，页面应显示占位，不把作者缺失当整个列表 500。该服务不返回密码字段。

所有 AOP 均有代理边界：不得依赖 new、final/private 方法、this.method() 触发权限或日志切面。正式入口遵照 [B-14](../api/B14权限注解接入.md) 和 [B-15](../api/B15操作日志接入.md)。

## 4 验收账号准备

在新的联调库执行已核对的身份与内容 SQL，使用专用管理员。通过注册创建独立编辑、审核、发布和待停用账号，再通过 B-13 分配 EDITOR/REVIEWER/PUBLISHER；待停用账号先登录，再用 B-11 停用以验证旧会话。真实密码保存在本机 ApiFox 环境。

权限以角色权限关系为准，不仅看角色名。管理员也没有隐式绕过。需要修改角色权限做撤权实验时记录原集合，实验后恢复，避免影响其他并行验收。不得在日常业务库反复执行初始化/清理。

## 5 实际接口验收矩阵

以下使用业务动作名称，实际路径必须在 A 交接后填写；没有假定 A 已实现某个路径。

| 编号 | 操作/前置 | 预期与数据检查 | 当前状态 |
| --- | --- | --- | --- |
| INT-01 | 新会话访问分类/文章后台查询 | 401、统一响应、requestId；数据无变化 | 待 A |
| INT-02 | 普通账号或缺少权限访问后台写入 | 403；文章、历史、成功日志均不新增 | 待 A |
| INT-03 | 有权限但缺少/错误 CSRF | 403；无业务副作用 | 待 A |
| INT-04 | 编辑创建文章，请求伪造 authorId/操作者 | 实际作者来自真实 CurrentUserContext | 待 A |
| INT-05 | 多作者文章分页 | UserReader 批量取作者；无逐文章身份查询 | 待 A |
| INT-06 | 编辑提交后直接审核或发布 | 缺相应权限返回 403，原状态/版本不变 | 待 A |
| INT-07 | 审核退回、编辑修改再提交、审核通过 | 状态合法，历史操作者与时间正确 | 待 A |
| INT-08 | 发布、公开查询、下架后公开访问 | 只公开允许的文章；下架后详情 404 | 待 A |
| INT-09 | 原会话撤权再操作 | 下一请求 403；不要求重新登录 | 待 A |
| INT-10 | 作者已有文章后停用，持旧会话访问 | 401、会话失效；历史文章/作者摘要仍可展示 | 待 A |
| INT-11 | 不存在对象、旧版本、非法状态动作 | 区分 404 与 409；失败不改状态/历史 | 待 A |
| INT-12 | 两个并发审核或旧版本编辑 | 不发生重复成功或覆盖；核对冲突响应 | 待 A |
| INT-13 | 批量发布中某条不合法 | 按约定全成全败；不得留下部分 SUCCESS | 待 A |
| INT-14 | 故障注入：业务异常/成功日志写入异常/提交失败 | 数据与成功日志一起回滚；失败日志遵循 B-15 | 待 A |
| INT-15 | 公开接口请求草稿、退回、停用分类内容 | 按 A 公开规则拒绝，不能仅靠前端隐藏 | 待 A |
| INT-16 | 字段校验、未知异常、跨模块响应 | 400/500 语义、UTC、requestId、无堆栈/敏感字段 | 待 A |

INT-06 仅验证是否持有动作权限；同一用户是否可以审核自己文章，还须按 A 最终规则明确后测试，不凭角色名臆造业务限制。
