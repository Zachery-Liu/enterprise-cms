# enterprise-cms A 与 B 模块任务分工

| 项目 | 内容 |
| --- | --- |
| 文档版本 | V1.0 |
| 编制日期 | 2026-09-14 |
| 依据 | 企业级 CMS 内容管理系统需求分析 V1.1 |
| 用途 | 明确两名成员的代码所有权、开发任务、依赖关系和完成标准 |
| 当前状态 | 开发任务基线，待双方确认技术版本和截止时间 |

## 1 分工原则

1. A 负责内容领域，包括分类、文章和文章状态机。
2. B 负责身份权限和公共能力，包括用户、角色、权限、登录、AOP 和操作日志。
3. 一张业务表、一条状态规则和一个后端入口只设一个负责人。
4. 每名成员负责自己模块的后端、必要页面、接口文档、测试和报告材料。
5. 公共代码由 B 主维护，A 在变更前共同评审，避免公共接口频繁变化。
6. 必做功能完成前不开发多站点、动态内容模型、完整素材库和复杂版本管理。

## 2 代码与数据所有权

| 范围 | A | B |
| --- | --- | --- |
| 数据表 | `cms_category`、`cms_article`、可选 `cms_article_status_history` | `sys_user`、`sys_role`、`sys_permission`、`sys_user_role`、`sys_role_permission`、`sys_operation_log` |
| 后端模块 | `category`、`article`、`publication` | `auth`、`user`、`role`、`permission`、`security`、`logging`、`common` |
| 核心规则 | 分类树、文章编辑、文章状态转换、批量发布 | 身份认证、权限计算、AOP 拦截、日志记录、统一异常 |
| 页面 | 分类管理、文章列表、文章编辑、待审核、发布操作 | 登录、用户管理、角色权限、日志查询 |
| SQL 优化案例 | 文章列表关联分类或作者 | 用户列表关联角色 |

A 是文章状态的唯一写入负责人。B 提供权限和登录上下文，但不得通过 Mapper 或 SQL 直接更新 `cms_article.status`。

## 4 A 模块任务

### A-00 内容领域设计

**依赖：** 无。

**任务：**

- [ ] 确定分类、文章和可选状态历史对象。
- [ ] 完成文章状态机：`DRAFT`、`PENDING`、`REJECTED`、`APPROVED`、`PUBLISHED`、`OFFLINE`。
- [ ] 明确各状态允许的操作和所需权限。
- [ ] 确定文章新增、编辑、查询、提交、审核、发布和下架接口。
- [ ] 与 B 确认当前用户对象、权限编码、日志注解和公共返回结构。

**完成标准：** 状态表、接口草案、权限对照表经过双方确认；客户端不能通过普通编辑接口直接传入文章状态。

### A-01 分类和文章数据库设计

**依赖：** A-00，B-00 提供用户主键类型和公共字段约定。

**任务：**

- [ ] 设计 `cms_category` 和 `cms_article` 字段、约束、索引及注释。
- [ ] 分类使用 `parent_id` 表示层级，统一根节点规则。
- [ ] 文章关联分类和作者，作者 ID 类型与 B 的用户表一致。
- [ ] 增加 `version` 乐观锁字段和 `deleted` 逻辑删除字段。
- [ ] 增加创建人、创建时间、更新人和更新时间等审计字段。
- [ ] 输出内容领域数据字典和 E-R 图信息。

**完成标准：** SQL 可从空库执行；常用筛选和关联字段具备合理索引；不存在双方定义不同 ID 类型的问题。

### A-02 多级分类管理

**依赖：** A-01，B-03 的权限注解可使用或已有临时兼容接口。

**任务：**

- [ ] 实现分类树查询、新增、编辑、移动、排序、启停和删除。
- [ ] 禁止将分类移动到自身或自己的后代节点下。
- [ ] 父分类不存在、停用或已删除时拒绝新绑定。
- [ ] 有子分类或有效文章引用时拒绝删除。
- [ ] 分类树采用一次查询后内存组装或批量查询，避免逐节点 N+1。
- [ ] 接入 `cms:category:read` 和 `cms:category:manage` 权限。

**完成标准：** 正常分类流程和循环、引用、停用等异常用例全部通过。

### A-03 文章基础管理

**依赖：** A-01、A-02，B-02 可提供当前登录用户。

**任务：**

- [ ] 实现文章新增、详情、编辑和逻辑删除。
- [ ] 新建文章默认为 `DRAFT`，作者来自当前用户上下文。
- [ ] 只允许 `DRAFT` 或 `REJECTED` 状态编辑。
- [ ] 使用请求版本号和 MyBatis-Plus 乐观锁防止静默覆盖。
- [ ] 已发布文章必须先下架，才能编辑或删除。
- [ ] 使用 DTO 接收参数、VO 返回数据，不直接暴露 Entity。
- [ ] 明确富文本保存或输出时的脚本注入防护策略。

**完成标准：** 两次使用相同旧版本号保存时，后一次返回 409；逻辑删除数据不会出现在普通查询中。

### A-04 文章查询和高级数据处理

**依赖：** A-03。

**任务：**

- [ ] 实现数据库分页，不在内存中截取结果。
- [ ] 支持标题模糊匹配、分类、状态、作者和时间范围筛选。
- [ ] 支持多字段排序，客户端排序字段必须经过白名单映射。
- [ ] 增加稳定次排序键，降低翻页时数据重复或遗漏。
- [ ] 使用 MyBatis-Plus 条件构造、逻辑删除、自动填充和分页插件。
- [ ] 批量操作限制单次数量。

**完成标准：** ApiFox 能验证分页总数、组合筛选和排序；非法排序字段和超大分页参数被拒绝。

### A-05 审核和发布状态机

**依赖：** A-03，B-03 权限 AOP，B-04 操作日志入口。

**任务：**

- [ ] 实现提交审核、待审查询、审核通过和审核退回。
- [ ] 退回必须填写原因并记录审核人和时间。
- [ ] 实现发布、下架和公开文章查询。
- [ ] 公开查询只返回 `PUBLISHED` 状态文章。
- [ ] 状态更新 SQL 同时校验文章 ID、原状态和乐观锁版本号。
- [ ] 对重复、非法和并发状态转换返回 409。
- [ ] 所有状态操作接入 B 的权限注解和日志注解。

**完成标准：** 编辑账号直接审核或发布被拒绝；草稿不能直接发布；完整生命周期可以重复执行。

### A-06 批量发布

**依赖：** A-05。

**任务：**

- [ ] 批量发布限制最多 50 条，并校验 ID 不重复。
- [ ] 执行前一次性检查文章存在性、状态和操作权限。
- [ ] 使用同一事务完成整批发布。
- [ ] 任意文章不合法或执行异常时整批回滚。
- [ ] 返回失败文章和具体原因，不返回数据库异常堆栈。

**完成标准：** 全部合法时全部成功；混入非法状态文章或制造中途异常时全部不生效。

### A-07 查询优化和模块测试

**依赖：** A-02 至 A-06。

**任务：**

- [ ] 检查文章列表关联分类和作者时的 SQL 次数。
- [ ] 使用联表或分页后批量查询解决 N+1，验证分页总数不受影响。
- [ ] 记录优化前后数据规模、SQL 次数、执行计划或耗时。
- [ ] 完成文章、分类、状态机、事务、权限和并发测试。
- [ ] 导出 A 模块 ApiFox 用例。
- [ ] 完成内容模块说明和本人开发总结。

**完成标准：** 优化前后返回数据一致；测试包含正常流程和异常边界；结果来自实际运行。

## 5 B 模块任务

### B-00 身份权限和公共契约设计

**依赖：** 无。

**任务：**

- [ ] 确定用户、角色、权限、关联关系和日志对象。
- [ ] 固定用户主键类型、账号状态和公共审计字段。
- [ ] 定义 `CurrentUser`，至少包含用户 ID、用户名和有效权限。
- [ ] 定义统一响应、分页响应、业务异常和错误码。
- [ ] 与 A 固定全部 `cms:*` 权限编码。

**完成标准：** A 可以只依赖公共接口开发，不需要自行创建另一套登录或权限工具。

### B-01 用户权限数据库设计

**依赖：** B-00。

**任务：**

- [ ] 设计用户、角色、权限、用户角色、角色权限和操作日志表。
- [ ] 用户名、角色编码和权限编码设置唯一约束。
- [ ] 关联表设置组合唯一约束和必要索引。
- [ ] 明确逻辑删除、账号停用及已删除用户名是否允许复用。
- [ ] 提供角色、权限、管理员和普通账号的演示初始化数据。
- [ ] 输出身份权限领域数据字典和 E-R 图信息。

**完成标准：** SQL 可从空库执行；不能通过文本字段代替用户角色和角色权限关联表。

### B-02 注册登录和用户管理

**依赖：** B-01、B-05 的基础异常与校验能力可以并行开发。

**任务：**

- [ ] 实现注册、登录、退出和当前用户查询。

- [ ] 密码使用安全的不可逆摘要保存，不写入日志和响应。
- [ ] 登录检查账号状态，退出后会话立即失效。
- [ ] 实现用户分页查询、状态筛选和账号启停。
- [ ] 明确会话 ID 的创建、失效和权限变更生效规则。

**完成标准：** 重复注册、错误密码、停用账号、未登录和退出后复用会话等测试通过。

### B-03 角色权限和 Spring AOP

**依赖：** B-01、B-02。

**任务：**

- [ ] 实现角色查询、用户角色分配和角色权限配置。
- [ ] 实现方法级 `@RequirePermission` 权限注解。
- [ ] 使用 Spring AOP 获取当前用户并校验有效权限。
- [ ] 区分 401 未登录和 403 无权限。
- [ ] 验证 A 的文章和分类接口确实经过权限切面。
- [ ] 检查 Spring 代理和同类内部调用，避免绕过切面。

**完成标准：** 管理员和普通账号调用结果符合权限表；直接调用受保护接口能证明允许与拒绝均生效。

### B-05 统一响应异常和校验

## 6 A 与 B 的交接契约

### 6.1 B 提供给 A

| 能力 | 最小接口或形式 | A 的使用位置 |
| --- | --- | --- |
| 当前用户 | `CurrentUserContext.getRequiredUser()` | 创建人、更新人、审核人和操作人 |
| 权限控制 | `@RequirePermission("权限编码")` | 分类、文章和状态接口 |
| 操作日志 | `@OperationLog(...)` | 新增、修改、删除、审核、发布和下架 |
| 统一异常 | `BusinessException` 与标准错误码 | 记录不存在、状态冲突和业务校验 |
| 统一响应 | `ApiResponse<T>`、`PageResponse<T>` | 全部 Controller |

公共类型的包路径和方法签名在 M0 后不得随意修改。

### 6.2 A 提供给 B 页面或联调

| 接口能力 | 权限 | B 的使用位置 |
| --- | --- | --- |
| 文章分页和详情 | `cms:article:read` | 待审核和发布页面 |
| 提交审核 | `cms:article:submit` | 编辑流程 |
| 审核通过或退回 | `cms:article:audit` | 审核操作 |
| 批量发布 | `cms:article:publish` | 发布操作 |
| 下架 | `cms:article:offline` | 发布管理 |
| 公开文章查询 | 匿名 | 演示已发布和已下架效果 |

B 不调用 A 的 Mapper，不直接更新文章表，不复制文章状态判断。

## 7 联调门禁

### G0 契约门禁

- [ ] 权限编码完全一致。
- [ ] 用户、分类和文章 ID 类型一致。
- [ ] 统一响应、分页和错误码一致。
- [ ] 文章状态机和批量事务语义一致。

### G1 权限门禁

- [ ] A 的至少一个文章查询接口接入 B 的当前用户和权限 AOP。
- [ ] 管理员允许访问，未登录返回 401，无权限返回 403。
- [ ] A 不存在临时硬编码用户或第二套权限判断。

### G2 数据门禁

- [ ] 文章正确关联分类和作者。
- [ ] 分类删除能检查文章引用。
- [ ] 用户停用不破坏历史文章和日志关联。

### G3 流程门禁

- [ ] 编辑创建文章并提交审核。
- [ ] 编辑账号审核被拒绝。
- [ ] 审核账号退回，编辑修改后重新提交并通过。
- [ ] 发布账号执行批量发布和下架。
- [ ] 公开接口只返回已发布文章。

### G4 日志和异常门禁

- [ ] 分类、文章、审核和发布操作均有日志。
- [ ] 事务回滚不会留下虚假的成功日志。
- [ ] 状态冲突返回 409，响应不包含堆栈。

### G5 交付门禁

- [ ] 从空库导入 SQL 后可以启动。
- [ ] ApiFox 用例能按说明重复执行。
- [ ] 设计图、接口和数据库与实际代码一致。
- [ ] 双方都能解释权限、状态机、事务和各自 SQL 优化案例。

## 8 Git 协作约定

- A 使用 `feature/content` 分支，B 使用 `feature/security` 分支。
- 公共基础调整使用短期独立分支，经双方确认后先合入 `main`。
- 提交信息说明具体结果，例如 `feat(article): add article status transitions`。
- 一个提交只处理一个清晰问题，避免功能、格式化和无关文件混在一起。
- 合并前执行编译、测试和对应 ApiFox 回归。
- 数据库变更使用新增迁移脚本，不覆盖已经共享的历史脚本。
- 禁止提交密码、数据库真实凭证、IDE 用户配置、构建产物和 Word 临时文件。
- 需求变更先修改文档，再修改接口和代码。

## 9 双方完成定义

个人任务只有同时满足以下条件才算完成：

- 功能代码已经合入并能启动，不是只有接口或页面空壳。
- 正常、异常、越权和边界用例已经实际验证。
- 接口文档、SQL、设计说明和代码保持一致。
- 没有绕过统一权限、异常和日志机制。
- 有可说明的 MyBatis-Plus 应用和 SQL 优化证据。
- Git 历史、AI 使用和人工修改记录真实完整。
- 能独立解释本人负责模块的业务规则和关键代码。
