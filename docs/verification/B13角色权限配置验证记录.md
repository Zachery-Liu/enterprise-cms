## 真实问题：锁等待后的事务内权限缓存

首次全量运行结果为 109 项中 1 项失败：`authorityRevokedWhileWaitingForLockCannotUseOldRequestSnapshot` 预期 403，实际返回 200。

复现顺序：

1. 管理请求通过初步鉴权，并在事务内获取当前用户快照，读取已有角色分配权限。
2. 另一连接持有共同管理写锁，使该请求等待；测试同步探针确认请求已到锁入口。
3. 持锁连接删除请求者的角色分配权限并提交。
4. 等待请求获取锁后再次调用同一权限 Mapper。虽然事务采用 READ_COMMITTED，但 MyBatis 一级缓存仍复用了先前结果，因此错误放行。

修复：将 B-13 所有 FOR UPDATE 查询设为 `flushCache=true`、`useCache=false`。获取管理写锁时清除事务内旧查询缓存，并保留锁后的实时账号与权限校验。未通过关闭鉴权或跳过该测试处理问题。

修复后完整 clean verify：109 项全部通过，上述复现返回 403。失败日志保存在仓库外 `../work/b13-verify-before-cache-fix.log`，最终日志在 `../work/b13-verify.log`。该记录可作为 B-20 真实问题分析素材，但 B 仍需自行复现并解释。
