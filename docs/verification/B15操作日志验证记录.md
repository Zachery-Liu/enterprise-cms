# B-15 操作日志验证记录

日期：2026-10-11。分支：`feat/operation-log`，起点为 B-14 `fcbff83`。本轮保留传统 SSM、JDK 17 和外部 Tomcat 架构，不引入 Spring Boot，也不新增业务 SQL 迁移。

## 1 实现范围

新增 `OperationLog`、`OperationLogAspect`、受限只读目标 ID 解析器及日志持久化服务，使用既有 `sys_operation_log`。已接入注册、用户角色分配、角色权限配置；登录成功/失败和退出使用独立会话日志路径。

数据库成功日志与业务数据同事务；写日志失败使业务回滚。外层回滚和提交阶段失败不会留下 SUCCESS；回滚后独立记录 FAILURE，独立日志故障不会替换原业务异常。原登录控制台日志继续保留。

全局 Spring 事务默认改为受检异常也回滚（`rollbackOn=ALL_EXCEPTIONS`），事务代理顺序为 0、日志切面为 200，避免外层忽略受检异常却尝试提交已标记回滚的事务。该行为及 A 的接入约束已写入公共契约和接入说明。

## 3 主要断言

- 真正的角色分配入口记录服务端操作者、目标用户、动作和 requestId；请求伪造的操作者字段及转发头不被信任。
- 成功、业务异常、受检异常、后续外层回滚、提交回调异常均与真实数据库结果一致。
- 故障注入让 SUCCESS 日志插入失败时，业务数据回滚，随后单独保存 FAILURE。
- REQUIRES_NEW 的已提交业务及日志不受无关外层回滚影响。
- 创建对象成功时从 `#result.id` 取目标；创建回滚时不保留未提交结果 ID。
- 目标无法解析记为 null；不允许借目标表达式读密码字段、调用方法、访问类型或执行赋值。
- 独立失败日志存储故障不覆盖原业务异常；登录日志存储故障也不改变已完成的会话结果。
- 登录成功使用已验证身份，失败不保存输入账号或密码；退出在 Session 销毁前捕获服务端用户 ID。
- 日志不含测试密码、密码摘要、CSRF 令牌、会话标识或异常中的敏感正文；未复制请求/响应对象。
- 普通查询与在拦截器/权限切面阶段被拒绝的请求不产生已执行业务的日志。
- 根容器 Service 与 MVC Controller 的日志代理均实际执行。

测试中初次使用数字 Mock Session ID 时，与记录 ID、日期数字产生字符串匹配误判，改为具有唯一前缀的模拟会话标识，不删减敏感信息断言。受检异常暴露的事务策略问题已通过明确全局回滚策略修正，并在 MySQL 再验证。

## 5 复验与交付边界

普通回归：`mvn clean verify`。真实日志专项：准备新的空 MySQL 库，设置 `CMS_MYSQL_TEST_URL`、`CMS_MYSQL_TEST_USER`、`CMS_MYSQL_TEST_PASSWORD` 后执行 `mvn -Dtest=MysqlOperationLogIT test`。该测试会建表并清理测试数据，不能指向日常业务库。RBAC 专项使用另一个空库，执行 `mvn -Dtest=MysqlAssignmentIT test`。

外部 HTTP 的环境变量沿用 SSM 迁移验收说明；现在测试还要求最新 B-15 日志实现，旧基线 WAR 不满足新增日志断言。

B-15 的 B 端代码与回归已完成。A 的分类/文章/审核/发布只提供注解示例和测试业务，未宣称真实 A 联调完成；也未实现 B-16 日志查询接口/页面或批次数量摘要扩展。代理、同步单数据源事务及 Session 日志例外详见[B-15 接入说明](../api/B15操作日志接入.md)。
