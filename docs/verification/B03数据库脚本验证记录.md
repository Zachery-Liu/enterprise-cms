## 3 密码摘要验证


## 5 A/B 外键联调结果

按正式顺序执行：

```text
001_identity_schema.sql
  -> 002_content_schema.sql
  -> 003_identity_seed.sql
```

`001_identity_schema.sql` 成功，说明 B 已提供 `sys_user(id BIGINT UNSIGNED)`。随后 A 的 `002_content_schema.sql` 在创建第一张表时失败：

```text
ERROR 3818: Check constraint 'chk_category_not_self_parent'
cannot refer to an auto-increment column.
```

问题位于 A 的 `cms_category`：

```sql
CONSTRAINT chk_category_not_self_parent
    CHECK (parent_id IS NULL OR parent_id <> id)
```

`id` 是自增列，MySQL 不允许该检查约束引用自增列。按照 A/B 模块边界，B 未修改 `002_content_schema.sql`。该规则应改由 A 的 `CategoryService` 保证，或由 A 选择兼容 MySQL 的其他实现。

为隔离验证 B 的外键兼容性，仅在内存中的临时测试副本删除上述 A 自有检查约束后，`002` 的其余内容成功执行，并建立以下 7 个指向 `sys_user.id` 的外键：

- `cms_category.created_by`
- `cms_category.updated_by`
- `cms_article.author_id`
- `cms_article.reviewer_id`
- `cms_article.created_by`
- `cms_article.updated_by`
- `cms_article_status_history.operator_id`

这说明 B 的表名、主键类型和外键目标与 A 设计一致；正式 `002` 仍需由 A 修复后重跑。
