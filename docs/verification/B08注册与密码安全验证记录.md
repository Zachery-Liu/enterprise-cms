新增测试验证：

- 独立 PBKDF2 测试向量可以校验；同一密码重复编码生成不同随机盐；错误密码不匹配，密码首尾空格不被擅自裁剪。
- 盐长度为 16 字节、输出为 32 字节、迭代次数为 600000；拒绝非法摘要及不受限的迭代次数。
- 注册请求规范化用户名和展示名称；密码只以摘要存储，字段校验失败不落库。
- 客户端携带 ADMIN、管理权限、DISABLED、deleted 或 createdBy 时，服务端仍只创建 ACTIVE 普通账号并分配 USER。
- 注册响应和 DTO 的序列化、字符串输出不泄露密码；注册不会写入登录用户 Session 键。
- 大小写/首尾空白规范化后的重复用户名返回 409，逻辑删除的用户名也不可复用。
- 默认角色缺失、停用或逻辑删除时，不创建用户。
- 通过真实数据库约束故意使角色关系插入失败，验证用户插入也回滚。
- 两个独立 Session 并发注册同名用户，结果恰好一个 201、一个 409，只保留一个用户和一条默认角色关系。
- 匿名获取 CSRF 令牌创建 Session；同会话令牌复用、不同会话令牌不同；缺少或跨会话使用令牌均返回 403，未写数据库。
- 新增 004 脚本的角色插入 DML 可重复执行，且不恢复已停用角色。

测试中的长 Session ID 避免短数字与时间或用户 ID 偶然重合，防止脱敏断言误报。所有测试用户和密码均为合成测试数据。

## 2 验证方式

注册测试使用完整 Spring Boot 上下文、MockMvc、真实密码编码器和真实 Mapper；两个并发请求分别使用独立 Session。注册事务由真实数据库连接执行，测试本身不包在一个外层回滚事务中，因此能观察提交和回滚结果。

测试通过 `test` 配置使用内存数据库，并额外固定注册测试数据库为 `b08_registration`；不继承应用的 MySQL 连接地址。每个用例只清理隔离测试库中的 B 表。

PBKDF2 固定向量使用 Node.js `crypto.pbkdf2Sync` 独立生成，Java 实现验证该固定向量。该向量采用与 B-01 一致的参数和存储格式；不声称已经用未知明文密码验证现有四个种子账号。

构建命令、E 盘缓存和临时目录设置沿用 [B-05～B-07 验证记录](B05-B07公共组件验证记录.md) 的复现步骤。原始结果位于 `target/surefire-reports`，构建产物不提交。此次依赖已缓存，验证离线执行。
