## 1 测试覆盖

新增 `SessionIntegrationTest` 共 15 项，既有 51 项继续通过。

- 正确密码登录成功，规范化用户名，忽略客户端伪造的 userId 和角色。
- 登录成功更换 Session ID、轮换 CSRF 令牌，Session 只保存可信用户 ID。
- 未知账号、密码错误、停用和已删除账号得到相同的 401 业务码及提示。
- 登录与退出均要求 CSRF，其他会话的令牌不能代用，登录前的旧令牌不能执行登录后的写请求。
- 退出销毁会话，再次获取匿名令牌后重复退出安全。
- 后台接口默认要求登录，请求参数/请求头的用户 ID 无效；Session 中类型非法的身份值会被拒绝并清理。
- 停用或逻辑删除已登录账号后，下一次受保护请求返回 401 并使原会话失效。
- 后台请求读取最新账号信息，不缓存旧展示名称。
- 登录 DTO 和认证事件摘要日志不包含密码、摘要、Session ID 或 CSRF 令牌。
- 字段错误返回 400，不把被拒绝的密码值回显。
- 新注册用户可以使用自己的密码登录，注册本身不会建立登录态。

## 2 真实 HTTP 与 Cookie

测试在 `127.0.0.1` 随机端口启动真实嵌入式 Tomcat，用 Java HTTP 客户端执行完整请求：

1. 获取匿名令牌和 Cookie，检查 HttpOnly、SameSite=Lax、Path=/。
2. 登录后确认服务端下发不同的 Cookie 会话 ID。
3. 携带新 Cookie 访问受保护测试接口成功。
4. 使用旧 Cookie 的另一个 HTTP 客户端访问同接口返回 401。
5. 容器实际会话空闲超时为 1800 秒。
6. 重新获取令牌，确认与登录前不同，携带它退出。
7. 使用退出前保存的新 Cookie 访问受保护接口返回 401。

测试辅助接口仅位于测试源码，不进入交付 JAR。服务随测试上下文关闭；数据库使用 `b09_session` 内存库，不连接用户的 MySQL。验证了容器配置的超时值和无效会话拒绝，未等待完整 30 分钟做自然超时试验，也未进行 HTTPS Cookie 实测。

## 3 实际排错记录

首轮 66 项测试中有 1 项测试准备错误：参数化用例中的 DISABLED 被拼接为 SQL 标识符，导致停用场景没有真正执行到业务断言。将状态值改为 JDBC 绑定参数后重跑，账号停用检查及全部回归通过。没有删除失败场景或放宽断言。
