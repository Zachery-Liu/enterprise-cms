# B-17 用户角色查询优化验证记录

日期：2026-10-12。分支 perf/user-role-query，起点为 B-11 e8cd81d。本轮实现列表角色批量读取并交付真实查询次数证据，不增加 SQL 迁移。

## 实现

GET /api/users 每行新增 roles，保留既有账号字段；启停响应保持 UserAdminView。正式查询先分页用户，再用本页 ID 批量查询角色，返回不可变集合；无角色返回空集合，逻辑删除角色排除，停用角色保留用于管理展示。原有效角色 Mapper 不变，不能用展示数组替代鉴权。

低效逐用户方案只存在于测试方法 naive 中。SQL 计数探针、测试数据和 MySQL 专项均在 src/test，不随 WAR 部署。

MySQL 最终复验采用隔离实例 127.0.0.1:33079 的新空库 cms_b17_roles_final_20261012，使用正式 schema；早期单独验证库为 cms_b17_roles_20261012。HTTP 使用专用 cms_ssm_http。没有修改日常业务实例。

120 个未删除账号（含 12 停用）、另 1 个删除账号、4 个角色、122 条关系。每页 10、20、100 条各 5 轮，JDBC 计数分别为：

| 页大小 | 逐用户对照 | 正式批量 | 结果 |
| --- | --- | --- | --- |
| 10 | 12 | 3 | 5 轮全部一致 |
| 20 | 22 | 3 | 5 轮全部一致 |
| 100 | 102 | 3 | 5 轮全部一致 |

断言比较整个 PageResponse，包含账号字段、顺序、角色和 total。额外覆盖全量分页无重复遗漏、无角色、多角色、停用账号/角色、逻辑删除过滤、条件组合、空页跳过角色查询、Mapper 空/null/重复 ID，以及 HTTP 原字段与权限行为。

最初 MyBatis StatementHandler 探针在单独运行通过，但全套多上下文运行漏计 COUNT。修正为包装测试 DataSource，在 JDBC prepareStatement 层直接计数后，重新执行全套及新的真实 MySQL 空库，所有断言通过。最终证据使用修正后的输出，不降低期望 SQL 数掩盖问题。

真实 HTTP 在原注册/登录/权限配置/账号启停/日志查询链路中追加账号 roles 数量、角色 ID 和 code 的断言，证明最终部署 WAR 返回了实际分配角色。
