# B-11 用户管理验证记录

日期：2026-10-11。分支 `feat/user-administration`，起点为 B-16 `a65db1a`。本轮补齐用户列表及账号启停，不新增数据库脚本。

## 实现范围

- GET /api/users：用户名包含匹配、状态、创建时间范围，稳定分页；只选择安全列，不读取密码摘要。
- PUT /api/users/{id}/status：状态和必填版本号校验、MyBatis-Plus 乐观锁及更新审计字段自动填充。
- 查询和修改分别由 cms:user:read、cms:user:manage 控制，写请求仍要求 CSRF。
- 禁止停用自己；启停与 B-13 授权共用第一把管理行锁，并在锁后重新读取操作者权限。
- 停用不能使最后一个有效 RBAC 管理账号失效；成功日志与变更同事务，日志失败回滚。
- 本轮不附带角色列表，不新增逐用户查询角色的低效实现。

## 关键验证

1. 分页总数、时间和 ID 倒序、同毫秒分页、空页、逻辑删除过滤、停用账号展示。
2. 用户名包含匹配与状态/UTC 时间 AND 组合；百分号、下划线等按字面值匹配，SQL 注入字符串不扩大结果。
3. 非法分页、非法状态、缺少时区、时间倒置、过高精度、未知/重复参数返回 400。
4. 未登录 401，无权 403；只读权限和管理权限分离；缺少 CSRF 拒绝变更。
5. 状态变化时版本增加，操作者/更新时间自动填充，角色关系与既有日志保留。
6. 停用用户登录失败；已有会话在下一次受保护访问时失效；恢复后重新登录成功。
7. 自停用、停用唯一 RBAC 管理员、已删除或不存在账号、非法目标及请求体。
8. 旧版本冲突；相同状态与当前版本可成功且版本不增加；伪造操作者、密码、角色和删除字段不生效。
9. 成功日志写入后注入故障，验证账号状态、版本和更新人全部回滚，无 SUCCESS 残留，独立 FAILURE 保存。
10. 两个相同版本的状态更新并发，结果为一个 200、一个 409。
11. 账号停用和另一管理员角色移除并发，结果为一个 200、一个 409，始终保留有效管理员。
12. 请求等待管理锁时撤销其权限，锁后复核返回 403，目标不变。

上述并发用例在真实 MySQL 再执行通过。全量回归的权限入口数量断言由 7 更新为 9，保留代理和权限保护检查。首次编译修正了测试源码通配导入导致的同名类型歧义，未更改业务验收标准。

实际 HTTP 验收在原有认证、CSRF、RBAC 和日志查询流程中加入用户列表、通过接口停用账号、会话失效、旧版本恢复失败及使用新版本恢复；不再用直接数据库 UPDATE 代替用户管理接口。通过数据库确认两次成功 SET_STATUS 审计记录。
