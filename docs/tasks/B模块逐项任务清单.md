## 1 使用方式

本清单将 BH-00 至 BH-07 高层工作包拆成可独立创建 GitHub Issue、编码、测试和提交的任务。细粒度任务统一使用 `B-01` 至 `B-20`；任务编号一经使用不再改变，新增工作使用后续编号。

每个任务应满足：

1. 开始前确认依赖任务已经完成，或已有双方同意的临时接口。
2. 一个任务对应一个清晰功能范围，不混入 A 的内容业务。
3. 完成代码后同步接口、测试和必要说明。
4. 提交信息使用任务建议中的前缀，具体文字可根据实现调整。
5. 合入前由 A 检查公共契约是否满足内容模块接入需要。

## 2 B 模块边界

B 负责：

- `sys_user`、`sys_role`、`sys_permission`、`sys_user_role`、`sys_role_permission`、`sys_operation_log`。
- 注册、登录、退出、当前用户和用户管理。
- 角色查询、权限查询、角色分配和权限配置。
- `CurrentUserContext`、`UserReader`、权限注解和 Spring AOP。
- 操作日志注解、切面和日志查询。
- 统一响应、分页结构、异常、校验和请求标识。

B 不负责：

- 不创建或修改 `cms_category`、`cms_article`、`cms_article_status_history`。
- 不通过 Mapper、SQL 或通用状态接口修改文章状态。
- 不重复实现分类、文章、审核、发布和下架业务规则。
- 可以开发审核或发布页面，但必须调用 A 提供的文章生命周期接口。
